# stable-diffusion-webui-reForge ExtraNetworks 最適化 - サマリー

## 問題

WebUI の txt2img / img2img タブ内の LoRA 読み込み（及び他の ExtraNetworks）で、3000個程度のアイテムがカード形式で表示される際、以下の問題が発生：

- **初期読み込みが非常に重い** (10秒以上)
- **スクロールが重い** (10-20 FPS)
- **検索・ソートが遅い** (0.5秒以上)
- **メモリ使用量が多い** (100+ MB)

**原因:** 仮想化（Virtual Scrolling）が実装されておらず、全3000個のカード要素が常にDOMに存在している。

## 推奨ソリューション

### **方法A: フロントエンド仮想スクロール（推奨）**

JavaScriptで仮想スクロール（Virtual Scrolling）を実装。見える領域のカードだけをDOMに保持し、スクロール時に動的に入れ替える。

**メリット:**
- ✅ Pythonバックエンド変更 0行（互換性100%）
- ✅ 実装リスク最小
- ✅ 既存拡張機能の影響なし
- ✅ 最大の効果（20倍高速化）

**修正ファイル:**
```
javascript/extraNetworks.js      (+200-300行)
html/extra-networks-pane.html    (+5-10行修正)
```

### **方法B: バックエンド ペーション（将来）**

Pythonで最初は100個だけ取得し、スクロール時に追加取得する。

**メリット:**
- 初期ロード超高速化
- サーバー負荷分散

**デメリット:**
- Pythonコード大幅変更（50+行）
- 実装複雑度高い
